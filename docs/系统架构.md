# 系统架构

## 1. 架构目标

MailPilot 将邮箱产品体验、Agent 推理、邮箱执行和文档索引拆开，避免任何一个供应商或连接器成为产品核心的硬依赖。

```text
桌面端 UI
    ↓
本地产品 API
    ├── 邮件查询服务
    ├── 附件预览服务
    ├── Agent 会话服务
    └── 审批服务
          ↓
本地核心
    ├── SQLite 与全文索引
    ├── 邮件同步器
    ├── 文档解析器
    ├── 策略引擎
    └── 凭据服务
          ↓
连接层
    ├── Apple Mail MCP
    ├── Apple Mail Connector
    ├── Gmail Connector
    └── IMAP / Exchange Connector
```

当前已落地的真实只读链路是：

```text
Apple Mail / Mail.app
    ↓
JXA Apple Mail Connector
    ↓
MailSyncService
    ↓
SQLite + FTS5 本地索引
    ├── 邮件 FTS5
    └── 附件文本分块 FTS5
    ├── MailPilot MCP Server（stdio）
    │      ↓
    │   DSH Runtime（可选兼容）
    └── Pi Agent Core（默认）
           ↓
       Agent 原生工具 / MCP 能力
           ↓
       AgentEvent 会话桥 + FileSessionStore
           ↓
       桌面端 UI
```

桌面端的本地访问链路是：

```text
React/Tauri WebView
    ↓ HTTP 127.0.0.1:3100
MailPilotLocalApi
    ├── /api/snapshot
    ├── /api/messages/:account/:mailbox/:message
    ├── /api/attachments/:account/:attachment/text
    ├── /api/sync
    └── /api/agent/sessions
        ↓
    SQLite/FTS5 与 Agent Runtime（默认 Pi，可选 DSH）
```

## 2. 分层职责

### 桌面端

负责邮件列表、线程、附件预览、Agent 对话、审批和账号设置。桌面端不直接访问 Mail.app，也不直接读取凭据。

### 本地产品核心

负责统一领域模型、数据存储、索引、预览、权限和审计。这一层是 MailPilot 的产品核心。

### Agent Runtime

负责会话、工具调用、Skills、任务循环和调度。Pi Agent Core 是默认执行器，其他 Runtime 通过适配器接入，未来可以继续替换或并行验证。

当前实现通过统一 `AgentRuntime` 契约隔离运行时差异。`PiAgentRuntime` 直接驱动 Pi 的 `Agent`、流式事件、工具调用、steer、follow-up 和 abort；`DshRuntimeAdapter` 通过 JSONL 子进程 transport 兼容 DSH。UI 只依赖 MailPilot 的可审计事件，不依赖任何运行时的内部思维链。

MailPilot 的产品 Session 是外层真相，包含账号作用域、状态、轮次和事件历史。Pi 的 Agent 是每个 Session 的执行器；MCP 是能力接口，不负责产品 Session、审批或账号权限。

### MCP Server

负责把 MailPilot 的只读查询、附件资源和受控写操作暴露给 Agent。MCP Server 不绕过策略引擎。

默认 Pi runtime 使用同一查询服务生成 Pi 原生工具，因此默认链路不需要再启动一个 MCP 子进程。MCP Server 仍然保留给 DSH、外部 Agent 和调试客户端使用，避免查询逻辑分叉。

### 连接器

负责把统一领域模型映射到具体邮箱系统。连接器必须支持账号作用域和幂等操作。

当前 Apple Mail 连接器已经实现账号、邮箱、邮件列表和正文读取；附件二进制抓取与所有写操作仍属于后续阶段。附件索引器可以独立接收文件字节并完成解析、分块和受控预览。

## 3. 关键原则

- 查询优先走本地索引，必要时回源邮箱确认。
- 写操作先创建执行计划，再经过审批。
- 连接器只操作明确的 `AccountRef` 和 `MessageRef`。
- 原始邮箱数据与解析后的索引数据分离保存。
- 所有外部内容进入 Agent 前都标注为不可信内容。
