# 系统架构

## 1. 架构目标

MailPilot 将邮箱产品体验、Agent 推理、邮箱执行和文档索引拆开，避免任何一个供应商或连接器成为产品核心的硬依赖。

```text
桌面端 UI
    ↓
本地产品 API
    ├── 邮件查询服务
    ├── 附件预览服务
    ├── Agent 会话服务
    └── 审批服务
          ↓
本地核心
    ├── SQLite 与全文索引
    ├── 邮件同步器
    ├── 文档解析器
    ├── 策略引擎
    └── 凭据服务
          ↓
连接层
    ├── Apple Mail MCP
    ├── Apple Mail Connector
    ├── Gmail Connector
    └── IMAP / Exchange Connector
```

## 2. 分层职责

### 桌面端

负责邮件列表、线程、附件预览、Agent 对话、审批和账号设置。桌面端不直接访问 Mail.app，也不直接读取凭据。

### 本地产品核心

负责统一领域模型、数据存储、索引、预览、权限和审计。这一层是 MailPilot 的产品核心。

### Agent Runtime

负责会话、工具调用、Skills、任务循环和调度。DeepSeek Harness 通过适配器接入，未来可以替换为其他 Runtime。

### MCP Server

负责把 MailPilot 的只读查询、附件资源和受控写操作暴露给 Agent。MCP Server 不绕过策略引擎。

### 连接器

负责把统一领域模型映射到具体邮箱系统。连接器必须支持账号作用域和幂等操作。

## 3. 关键原则

- 查询优先走本地索引，必要时回源邮箱确认。
- 写操作先创建执行计划，再经过审批。
- 连接器只操作明确的 `AccountRef` 和 `MessageRef`。
- 原始邮箱数据与解析后的索引数据分离保存。
- 所有外部内容进入 Agent 前都标注为不可信内容。
