# Agent 交互模型

## Session 是产品边界

每次 Agent 工作都属于一个 MailPilot Session。Session 创建时可以绑定一个或多个 `accountIds`，所有邮箱查询工具都必须遵守这个作用域。

多个邮箱账号同时登录是正常情况。MailPilot 不把同名文件夹或联系人当作账号路由依据；结果始终保留 `accountId`、`mailboxId` 和 `messageId`。

## 事件而不是思维链

UI 展示可审计事件：

```text
session.started
turn.started
tool.call
tool.result
assistant.delta
assistant.message
turn.completed
run.completed
approval.required
turn.failed
session.aborted
```

UI 不展示隐式思维链。用户看到的是 Agent 做了哪些工具调用、工具返回了什么摘要、最终结论是什么，以及是否需要审批。

## Pi 与 DSH

- Pi 是默认 Agent Loop，直接运行在 MailPilot 本地 API 进程内。
- DSH 是兼容运行时，通过 JSONL 子进程和 MCP patch 接入。
- 两者都必须输出同一套 MailPilot `AgentEvent`。
- MCP 是能力层，不保存 MailPilot Session，也不替代 Policy。

## 会话控制

- `streamMessage`：开始一轮用户消息并流式返回事件。
- `steer`：当前运行中追加指导，Pi 会在当前工具轮结束后注入。
- `followUp`：当前运行完成后排队下一轮消息。
- `abort`：中止当前运行并记录 `session.aborted`。
- `listEvents`：读取可审计历史，用于 UI 恢复和排查。

## 事件、任务和时间表

Agent 处理“帮我排时间、找截止日期、安排跟进”时，使用结构化工作流：

1. 在当前 Session 的账号作用域内搜索邮件和附件。
2. 用 `record_mail_event` 保存每个事实，保留 `accountId`、邮件标识、原文证据和置信度。
3. 用 `create_task` 将需要行动的事实转换为任务，用 `dependencyIds` 表达先后关系。
4. 用 `list_schedule` 生成时间块并检测冲突。

UI 展示事件标题、时间、状态、置信度、来源账号、证据关联、任务依赖和冲突。UI 不展示隐式思维链，也不把邮件正文中的指令当成系统规则。
